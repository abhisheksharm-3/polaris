# OKR lens on `/sweep` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the `/sweep` command the user already runs twice a day also pace and capture their OKR progress, gated on the presence of an OKR ledger.

**Architecture:** One new deterministic shell helper (`scripts/okr-pace.sh`) owns the date-and-ratio pace math, mirroring `scripts/sweep-window.sh`. Two seed templates give the user a ledger and a progress file to fill once. The lens itself is added to `commands/sweep.md` as instructions: a step-1 ledger gate, a morning "OKR — today" section, an evening interview, and an `--okr-review` mode. Local files under `~/.claude/polaris-memory/okr/` hold the state; the ledger's existence is the on/off switch.

**Tech Stack:** Bash + `jq` (the plugin's only runtime tools), markdown command files, the plugin's inline shell test harness (`tests/run-tests.sh`).

## Global Constraints

- No compiled code, no package manager, no new dependency. Bash and `jq` only, matching the plugin. (Spec: Non-goals)
- The lens is off unless `~/.claude/polaris-memory/okr/ledger.md` exists; a plain `/sweep` must behave exactly as today when it is absent. (Spec: Scope)
- No source ever books progress. Only the evening interview answer advances a KR. (Spec: Non-goals)
- `~/.claude/polaris-memory/okr/log.md` is the source of truth; `~/.claude/polaris-memory/okr/progress.json` is a cache the review can rebuild. (Spec: Assumption 5)
- Every emitted line, code and prose, passes the writing standard (`rules/writing.md`) and the quality gate. Check prose with `bash scripts/check-patterns.sh prose <file>`. (Spec: Acceptance — writing standard)
- Times are UTC ISO-8601; dates may be date-only (`YYYY-MM-DD`). The command must not do date math in prose (core Rule 5). (Spec: The pace helper)

- [ ] **Step 3: Write the helper**

Create `scripts/okr-pace.sh`:

```bash
#!/usr/bin/env bash
# Per-KR OKR pace for the /sweep OKR lens. Deterministic: the command must not do this date/ratio
# math itself (core Rule 5). Emits a JSON array on stdout, one object per KR.
set -euo pipefail

now=""; progress=""
while [ $# -gt 0 ]; do
  case "$1" in
    --now) now="${2:-}"; shift 2 ;;
    --progress) progress="${2:-}"; shift 2 ;;
    *) echo "okr-pace: unknown arg: $1" >&2; exit 2 ;;
  esac
done
[ -n "$now" ] || { echo "okr-pace: --now <iso-or-date> required" >&2; exit 2; }
[ -n "$progress" ] && [ -f "$progress" ] || { echo "okr-pace: --progress <existing file> required" >&2; exit 2; }

jq -c --arg now "$now" '
  # A date-only string (length 10) gets midnight UTC appended before parsing.
  def ep: (if (. | length) == 10 then . + "T00:00:00Z" else . end) | fromdateiso8601;
  ($now | ep) as $n
  | (.periodStart | ep) as $p0
  | .krs | map(
      if (.kind // "num") == "flag"
      then { id: .id, status: "flag", done: (.current >= .target) }
      else
        (.deadline | ep) as $d
        | (if $d <= $p0 then 1 else (($n - $p0) / ($d - $p0)) end) as $ef0
        | (if $ef0 < 0 then 0 elif $ef0 > 1 then 1 else $ef0 end) as $ef
        | ($ef * .target) as $expected
        | ($expected - .current) as $gap
        | if $gap > 0.5 then { id: .id, status: "behind", needToCatch: ($gap | ceil) }
          elif (.current - $expected) > 0.5 then { id: .id, status: "ahead" }
          else { id: .id, status: "on-track" }
          end
      end
    )' "$progress"
```

Then make it executable:

```bash
chmod +x scripts/okr-pace.sh
```

Note on the "ahead" threshold: a KR is "ahead" only when `current − expected > 0.5`. When you run Step 4, read the real output and, if the O3-KR1 fixture (3/4 at 2026-07-28, expected ≈ 2.59, margin ≈ 0.41) does not clear that threshold, change the O3-KR1 fixture `current` to `4` in Step 1 so the "ahead" case is unambiguous. Do not loosen the threshold to force the test green.
