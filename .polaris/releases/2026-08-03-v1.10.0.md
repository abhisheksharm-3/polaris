# Polaris 1.10.0 — flows that pick themselves

Polaris had 29 commands and one flow. The flow lived in markdown a model could abridge, and every
path started with a typed command, so the day's work followed a Polaris path only when you
remembered a path existed and picked the right one.

## Describe the work; Polaris picks the path

Say what you want done. A hook classifies it, opens a run for it, and tells you which flow it chose.

```
> the referral code field accepts duplicates

Polaris routed this to the bug flow and opened run 'the-referral-code-field'.
Phases: reproduce -> rootcause (stop for approval) -> fix -> verify -> ship
Start with: reproduce via agent:bug-fixer
```

A question routes nowhere and opens nothing. A task matching no flow goes to `/polaris:compose`,
which builds one from the agents and commands you have installed.

## Eighteen flows, and a flow is a table row

`rules/flows.json` holds them: `bug`, `feature`, `incident`, `release`, `security`, `audit`, `qa`,
`cleanup`, `modernize`, `docs`, and the rest. Each is an ordered phase list naming a fleet agent, a
command, or a workflow. Adding one is a row, not a script. Sixteen of the eighteen compose commands
that already shipped.

`/flow` is now the `feature` row rather than a second description of it.

## The gates hold the order

A run's ledger lives at `.polaris/runs/<slug>/state.json`, and four gates read it:

- A dispatch the current phase does not name is refused.
- A phase command whose predecessor has not been earned is refused.
- The end of a turn is blocked to ask for the phase, or the approval, the run is waiting on.
- A dispatch below an agent's floor in `rules/model-floor.json` is refused, so the tier policy is
  enforced where it decides cost and quality rather than described in a rules file.

A phase is done only with its artifact on disk and its hash matching, so an artifact edited after
the fact invalidates the phase that claimed it.

`/polaris:pause` clears a run. `"routing": false` in `.polaris/config.json` turns all of it off.

## Three workflows for the phases that fan out

- `verify` sweeps from four angles until two consecutive rounds find nothing new, then puts every
  finding through three verifiers with different lenses, each told to refute it.
- `review` runs seven dimensions in a pipeline, with the over-engineering axis mandatory.
- `build` splits a plan, isolates only the slices that touch the same files, and carries a capped
  fix loop per slice. A slice that will not come clean is named, not swallowed.

## Also

The clarity check moved off the session model. `enhance-prompt` no longer asks a model to audit the
prompt it is already reading; a small-model hook does it and refuses only a prompt naming neither a
target nor an action.

Point `statusLine` at `scripts/statusline.sh` to see the open run.

## Upgrading

Nothing to do. Routing is on by default and needs no new config key, but it stays out of any project
without a `.polaris/config.json`.
