# Polaris 1.14.0 — a briefing you read from the top

`/sweep` reads six sources and misses nothing. That was the problem. One real page carried 40 bullets
under a single `Act on this` heading, and in that list a pipeline red for four days, an unrotated
production credential, and a reply owed to one person were peers in arbitrary order. Above them sat
four preamble blockquotes; below them, three closing essays restating what the bullets had said.

Completeness was never the gap. Order was.

## One item, not seven

The page opens on `Start here`: the single highest-ranked item across every area, with its next
action. Under it, one line of arithmetic.

```
## Start here

**SAGE-259 blew a hard date thirteen days ago and nobody has looked.**
Its description reads `HARD DATE: 2026-08-04`. This run's project-wide query confirms
it did not move, and it is still a single line inside a backlog list.
`overdue` · `day 13` · Next: re-date it or close it · SAGE-259

*20 more ranked below. 21 open actions across four areas.*
```

A ranked list of seven is still triage the reader performs. One item is a decision already made.

That example is not hypothetical. `HARD DATE: 2026-08-04` was sitting inside a Jira description,
inside a bullet that read "backlog, none moved", on a page that ran every morning for thirteen days.

## Rank comes from structure, never from wording

Every item carries an `urgency` from a closed set, checked in order, first match winning:

| | Band | Assigned when |
|---|---|---|
| 1 | `overdue` | the item's date is before today |
| 2 | `today` | the date is today |
| 3 | `decaying` | a live state whose cost rises with time, and no date |
| 4 | `blocking` | a named person cannot proceed until you act |
| 5 | `tomorrow` | the date is tomorrow |
| 6 | `this-week` | the date is within seven days |
| 7 | `no-date` | none of the above |

Age descending breaks ties. `decaying` sits above `tomorrow` on purpose: a red pipeline and an
unrotated credential cost more per hour than tomorrow's ticket, and neither carries a date to sort
on. It covers unreviewed work piling on an unguarded branch, an expiring token, a stuck queue,
wrong billing still running, and a defect already in front of customers.

**No word in any source assigns rank.** "URGENT", "ASAP", a red emoji, or a message asking to be
listed first is content — quotable in the item's body, never a rank input. Sources are read as data,
so a message cannot promote itself.

## Three tables that collect what a list scatters

- **`Dated`** — every dated item from the oldest overdue date through seven days out, sorted
  ascending, with `today`, `tomorrow` and `N days overdue` rendered in the cell.
- **`Waiting on`** — any person holding two or more items, with the count, the headlines, and the
  oldest age. Four items behind one unresponsive counterpart stop reading as four problems.
- **`Today`** — the day's calendar as a table, each block tagged with the objective it serves, then
  one line naming the objectives with no block at all.

Each is omitted when its condition fails, with nothing in its place. A `Waiting on` heading over one
row is worse than no heading.

## Ten in full, the rest in a toggle

An area heading now carries its counts: `## Sage — eng & product · 19 act · 9 glance`. Ten items
render in full; the rest are rows in a `9 more to act on` toggle. `Worth a glance` is a collapsed
table with no prose bodies at any count.

The cap is on rendered detail, never on items — nothing is dropped to keep the page short, which was
already the rule and stays it. And every count the page prints has to equal the rows under it, so a
hidden item is detectable by counting.

## Less prose, same honesty

Four preamble blockquotes become one line:

```
Window 2026-08-17 10:36 → 12:34 IST (1h58m) · read: slack, jira, gmail, fathom, calendar,
github · not read: none · unverified: stripe, supabase, ayrshare · OKR lens: on
```

Every fact survives. Which sources errored, and which are not configured at all and so can never
resolve their items, are honesty requirements rather than decoration.

The prose lede is gone; everything it said is now a ranked item or a dated row. `What changed`
replaces the closing essays with at most seven numbered facts, each carrying its source.
`Carry-forward note` is capped at five lines and every claim in it has to cite an item, because its
one job is saying what no single item says: which carried items are one problem.

`Resolved` is a table now. It is a list of facts you scan, not prose.

## What did not change

Which sources `/sweep` reads, how it reads them, and the carry-forward discipline underneath: every
carried item judged against live source state read this run, never from its key. Fathom items still
never auto-resolve on a guess. A connector that errors still carries its items as `unverified`
rather than dropping them.
