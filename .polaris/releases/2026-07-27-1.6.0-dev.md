# Polaris 1.6.0 — dev and client notes

## The headline

Polaris can now write the release notes themselves: `/polaris:notes` reads a git range once and
produces two documents, one for the dev team and client and one for the people who use the product
([`87600a9`](https://github.com/abhisheksharm-3/polaris/commit/87600a9)).

## Before you deploy

- **The command goes live on the next plugin update, not at commit.** Polaris runs from an installed
  plugin cache, so `commands/notes.md` landing in the repo does not make `/polaris:notes` callable
  until the plugin is updated in the environment that runs it. Skip the update and the slash command
  stays absent, with no error to explain why.

No breaking changes, no migration, and no new or changed config key in this release.

## New

- **`/polaris:notes [version]`** — `commands/notes.md`. Detects the change range in this order: a
  `dev`/`develop`/`staging`/`release/*` branch ahead of the base branch (three-dot range against the
  merge base), else the latest tag to `HEAD`, else the last 50 commits resolved via
  `git rev-list --max-count=1 --skip=50 HEAD` (falling back to the full history against the empty tree
  when the repo has fewer than 50 commits). It shows the commit count, changed-file count, and date
  span, then stops for confirmation before reading further — a project that ships by merged-PR window,
  tag pair, or Jira fix version says so at that prompt instead.
  ([`87600a9`](https://github.com/abhisheksharm-3/polaris/commit/87600a9))
- Reads the diff behind any commit whose message does not already say what changed, classifies every
  change as feature, improvement, fix, breaking change, deprecation, security fix, or internal-only,
  and collapses each merge commit into the one change it merged.
  ([`87600a9`](https://github.com/abhisheksharm-3/polaris/commit/87600a9))
- Dispatches `researcher` to establish the ICP for the product-facing document from the repo, the
  market, and close competitors, and states that judgment under **Written for** so the sender can
  correct it before sending. Dispatches `tech-writer` once per document to write both files to
  `.polaris/releases/`. ([`87600a9`](https://github.com/abhisheksharm-3/polaris/commit/87600a9))
- Offers to publish the dev document to a GitHub release (`gh release edit <tag> --notes-file <path>`),
  either document to Notion, or the product document to Slack — only after the user confirms in a
  later turn, and only to the destination they name.
  ([`87600a9`](https://github.com/abhisheksharm-3/polaris/commit/87600a9))
- Carries the version bump to 1.6.0 in `.claude-plugin/plugin.json` and
  `.claude-plugin/marketplace.json`, the `/notes` row and Release-section note in `README.md`, and the
  1.6.0 entry in `CHANGELOG.md`. ([`87600a9`](https://github.com/abhisheksharm-3/polaris/commit/87600a9))

## Deprecated

Nothing deprecated. `/polaris:release` is unchanged — it still owns the version, changelog entry,
manifest bump, and tag.

  ([`5f2f11f`](https://github.com/abhisheksharm-3/polaris/commit/5f2f11f))
