# Polaris 1.11.0 — a review you can afford to run

`/polaris:review` worked. It cost 40-50% of a session, which meant the honest thing to do with it
was skip it, and a quality gate you skip is not a quality gate.

## Where the money went

Two numbers, and only one of them was the obvious one. Seven dimensions at high effort is a fixed
seven agents. The confirmation stage spawned one verifier per finding, so seven dimensions raising
five findings each dispatched 42 agents, and nothing in the code capped the second number. You could
not tell what a run would cost before starting it.

## Four levels, one table

```
/polaris:review                 # high, the default
```

| level | dimensions | effort | confirms | worst case |
|---|---|---|---|---|
| `low` | correctness, over-engineering | low | nothing | 2 agents |
| `mid` | + security, tests | medium | high severity | 8 agents |
| `high` | all seven | high | high and medium | 14 agents |
| `critical` | all seven | high | everything, three lenses | 28 agents |

`high` is the default, so an existing dispatch keeps today's seven dimensions and effort. Every
level runs the over-engineering axis, because a review that omits it is sent back by `guard-review`.

## Confirmation stopped scaling with findings

One verifier per dimension now judges that dimension's eligible findings together, instead of one
verifier per finding. `critical` runs three verifiers per dimension, one per refutation lens, and a
finding survives on a majority — the same rule `verify.js` already used.

A finding below its level's threshold still reaches the report, marked `unconfirmed`. Nothing is
dropped to save money; it is labelled as unjudged, which is what it is.

## What the review of this change found

The build fanned out over its own diff and came back with eleven findings across three rounds. Two
mattered:

- `Object.hasOwn` runs its key through `ToPropertyKey`, so `level: ["critical"]` coerced to the
  string `critical`, passed the allowlist, and ran all 28 agents. Reachable from plain JSON.
- The majority counted verdicts rather than lenses, so one lens repeating its verdict three times
  outvoted the other two and confirmed a finding two lenses had refuted.

Both are fixed, and the acceptance run drives the real file through all twelve criteria.

The suite gained an assertion worth naming: it checks every level's key list against the dimension
list. The previous guarantee was a whole-file grep for `over-engineering`, which stays green when
the axis is dropped from a single level — the exact deadlock the guarantee existed to prevent. That
mutation and a misspelled key both fail now. 186 assertions, no skips.

## Known, and left alone

No `.catch` on a dispatch, so one rejected agent promise still discards the other dimensions'
findings. This behaves identically before this release, so it is not a regression, and it is the
next thing worth fixing here.
