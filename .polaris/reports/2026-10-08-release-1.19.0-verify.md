## Pass 1: workflow:verify at high, stopped at 40 agents

Stopped by the user as too large. Round 1 had found 40 findings and the judges confirmed all 8 high
ones by reproduction: surfaces failing open on an unknown token, frozen at first capture, and read
from any artifact; routing classes above `conversation`; `guard-bypass` evasions; permanent waivers
and free skips in `guard-tests`; the router quadratic on long prompts under bash 3.2. All fixed. The
size itself was fixed at the root in `workflows/verify.js`: high is 2 rounds and 2 lenses, at most
28 agents, reading the diff once.

## Pass 2: workflow:verify at high under the new cap, 24 agents

36 findings, 10 high confirmed, most of them holes in pass 1's fixes: an amended spec not
re-opening a skipped threat model; path staging turning off the comment law under any user `rules/`
directory; a file path pasted into a `sed` script; a 1-1 vote silently dropping a finding; quoted
flags and `bash -c` evading `guard-bypass`; `guard-tests` counting commented-out assertions and
missing `.only` and shell rewrites. All fixed, each with a test that fails on the old code.
`guard-bypass` was declared a speed bump rather than chased further; branch protection is the wall.

A separate security review flagged path traversal in `guard-edit` staging. Fixed by dropping `.`
and `..` segments; a class test over three traversal shapes fails on the old code.

## Pass 3: one verifier on the 10 confirmed fixes

8 held. 2 regressions in the fixes themselves, both fixed and pinned:

- `record spec` advanced past its own approval, because re-pointing `current` ran on every spec
  record and counted a done-but-unapproved phase as passed. Now it re-points only when a skipped
  phase re-opened, and stops at a phase waiting on approval.
- `guard-tests` refused running a test with redirected output, because any redirect plus any test
  token tripped it. Now it reads only write targets: the target of `>`/`>>`, `tee` operands, in-place
  `sed`/`perl` operands, and the `cp`/`mv` destination.

Also fixed from pass 3: `queue.pending()` and Python `fit()` read as skips; an attached or escaped
`-m` value read as a bypass flag; a finding with no returned judge vanished instead of reporting
`unjudged`.
